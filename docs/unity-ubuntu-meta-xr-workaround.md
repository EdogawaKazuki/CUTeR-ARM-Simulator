# Ubuntu workaround: Meta XR `OVRProjectConfig` editor error

## Summary

On Ubuntu/Linux, this Unity project can hit a Meta XR editor-side exception while opening the project:

```text
System.TypeInitializationException: The type initializer for 'OVRProjectConfig' threw an exception.
System.ArgumentOutOfRangeException: Specified argument was out of the range of valid values.
Parameter name: count
at System.Linq.Enumerable.Range(...)
at OVRProjectConfig..cctor()
.../Library/PackageCache/com.meta.xr.sdk.core@201.0.0/Editor/OVRProjectConfig.cs:116
````

The issue has been observed with:

```text
Ubuntu / Linux Editor
Unity 2022.3.62f1c1
Meta XR Core SDK 201.0.0
```

This blocks or pollutes the Unity Editor startup/import flow on Linux, even though the project can compile and build for Android after the local workaround is applied.

## Why this is a local workaround

The failing file is generated by Unity Package Manager under:

```text
Source/CUTeR Arm Simulator v2/Library/PackageCache/com.meta.xr.sdk.core@201.0.0/Editor/OVRProjectConfig.cs
```

`Library/` is Unity-generated local state and should not be committed.

Because of that, this repo does **not** commit the patched `OVRProjectConfig.cs` file directly. Instead, the repo includes a small patch script that Linux developers can run after Unity resolves packages.

## What the patch changes

The problematic code currently looks like this:

```csharp
public static int[] horizonOsSdkVersions = Enumerable.Range(minSdkVersion, currentSdkVersion - minSdkVersion + 1)
        .Concat(Enumerable.Range(version2Start, currentSdkVersion - version2Start + 1))
        .Except(skippedSdkVersions)
        .ToArray();
```

On Linux, the calculated `count` passed to `Enumerable.Range(...)` can become negative, which triggers:

```text
ArgumentOutOfRangeException: Parameter name: count
```

The workaround clamps the range count to at least `1`:

```csharp
public static int[] horizonOsSdkVersions = Enumerable.Range(minSdkVersion, System.Math.Max(1, currentSdkVersion - minSdkVersion + 1))
        .Concat(Enumerable.Range(version2Start, System.Math.Max(1, currentSdkVersion - version2Start + 1)))
        .Except(skippedSdkVersions)
        .ToArray();
```

This is intended only to unblock the Linux Unity Editor. It is not a vendor fix for the Meta XR package.

## How to apply the workaround

Close Unity first.

From the repository root, run:

```bash
./tools/patch-meta-xr-ovrprojectconfig-linux.sh "Source/CUTeR Arm Simulator v2"
```

Then reopen the project in Unity.

## When to rerun the script

Rerun the script after any of the following:

* `Library/` is deleted.
* `Library/PackageCache/` is regenerated.
* Unity Package Manager refreshes packages.
* Meta XR packages are updated.
* A fresh clone is opened for the first time.
* The error comes back after switching branches.

## Verification

After running the script, this command should show `System.Math.Max(...)` in both range counts:

```bash
grep -n "horizonOsSdkVersions" -A4 \
  "Source/CUTeR Arm Simulator v2/Library/PackageCache/com.meta.xr.sdk.core@201.0.0/Editor/OVRProjectConfig.cs"
```

Expected shape:

```csharp
public static int[] horizonOsSdkVersions = Enumerable.Range(minSdkVersion, System.Math.Max(1, currentSdkVersion - minSdkVersion + 1))
        .Concat(Enumerable.Range(version2Start, System.Math.Max(1, currentSdkVersion - version2Start + 1)))
        .Except(skippedSdkVersions)
        .ToArray();
```

Then reopen Unity and check the Console.

The important error that should disappear is:

```text
OVRProjectConfig
ArgumentOutOfRangeException
Parameter name: count
```

Compiler warnings such as `CS0618`, `CS0219`, and `CS0414` are separate pre-existing code warnings and are not handled by this workaround.

## Troubleshooting

### The script cannot find `OVRProjectConfig.cs`

Open the Unity project once and let Package Manager finish resolving packages. The file only exists after Unity creates `Library/PackageCache`.

Then rerun:

```bash
./tools/patch-meta-xr-ovrprojectconfig-linux.sh "Source/CUTeR Arm Simulator v2"
```

### The repo has multiple Unity projects

Pass the main Unity project path explicitly:

```bash
./tools/patch-meta-xr-ovrprojectconfig-linux.sh "Source/CUTeR Arm Simulator v2"
```

### Unity warns about `.bak` files in an immutable package folder

Earlier manual patch attempts may have created backup files next to `OVRProjectConfig.cs`.

Remove them with:

```bash
find "Source/CUTeR Arm Simulator v2/Library/PackageCache/com.meta.xr.sdk.core@201.0.0/Editor" \
  -maxdepth 1 \
  -name 'OVRProjectConfig.cs.bak*' \
  -delete
```

The patch script also removes these stale same-directory backup files automatically.

### The error comes back

Unity probably regenerated `Library/PackageCache`.

Rerun:

```bash
./tools/patch-meta-xr-ovrprojectconfig-linux.sh "Source/CUTeR Arm Simulator v2"
```

## Limitations

This workaround:

* Patches generated package-cache code.
* Is local to the developer machine.
* Can be overwritten by Unity.
* Is intended for Ubuntu/Linux Editor bootstrap only.
* Does not replace an official Meta XR package fix.
* Should not be needed on Windows if the team develops there without this error.
* Should be removed once the upstream package no longer throws this exception.

Do not commit anything under:

```text
Library/
Temp/
Obj/
Logs/
UserSettings/
```
